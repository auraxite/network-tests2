# Алгоритмы автоматического определения числа измерений задержки

Модуль `delay_measurements_amount_auto.{c,h}` реализует критерии останова
серии измерений из ВКР А.П. Волчанинова «Разработка алгоритмов автоматизации
сбора задержек на основе анализа внутренней структуры серии измерений задержки
в сети» (ВМК МГУ, 2024, научный руководитель А.Н. Сальников), глава 6:

- критерий (3): min / max скалярной величины по случайным окнам > k_scalar
  (ScalarMinAlgo, ScalarAvgAlgo, ScalarDevAlgo, ScalarMedAlgo);
- критерий (4): 1 − (среднее попарное расстояние спектров окон) /
  (средняя норма спектра) > acc (SpectrumFFTAlgo, ModifiedSpectrumFFTAlgo —
  без константной гармоники).

У алгоритмов две реализации одного автора:

- C — этот модуль, работает внутри clustbench во время замеров (ВКР, глава 7;
  коммит `fb01a1b`, 20.05.2024);
- Python — `utils/algo_demo.py`, прогон критериев по записанным сериям. На нём
  получены результаты и пороги главы 8 ВКР (раздел 8.4).

## Ошибки C-реализации (исправлены 20.10.2026)

| Место | Было | По тексту ВКР и в `algo_demo.py` | Последствие |
|---|---|---|---|
| `deviation_counter` | Σx² − (Σx)², без деления на длину окна | дисперсия Σx²/n − (Σx/n)² | значение отрицательное, отношение min/max двух отрицательных чисел больше 1, ScalarDevAlgo останавливался на первой проверке при любых параметрах |
| `fft_power_spectrum_counter` | квадрат модуля re² + im² (так и в исходной версии на FFTW2) | модуль коэффициента \|X\| (ВКР, разд. 5.5: «посчитать модули», `np.abs(rfft(...))`) | другие расстояния и нормы в критерии (4), пороги из ВКР не соответствуют |
| `scalar_criterion`, `spectrum_criterion` | окно длины int(ratio · cur_iter) могло быть 0 или 1 | — | обращение к пустому окну, деление на ноль. Теперь при окне короче 2 значений критерий возвращает 0 (измерения продолжаются) |

ScalarDevAlgo — один из двух алгоритмов, которые ВКР рекомендует (разд. 8.5).
До исправления в clustbench он не работал.

Ранее, в коммите `cbe21fb` (20.03.2026), были инициализированы нулём
накопители в `average_counter`, `deviation_counter` и `spectrum_criterion`
(в исходной версии они не инициализировались) и вычисление спектра
переведено с FFTW2 (`rfftw`) на FFTW3.

## Оставшиеся расхождения с `utils/algo_demo.py`

C-модуль следует тексту ВКР. Python-версия, на которой подбирались пороги,
в нескольких местах от текста отличается, поэтому пороги главы 8 напрямую в
clustbench переносить нельзя:

| | Текст ВКР и C | `utils/algo_demo.py` |
|---|---|---|
| Нормировка суммы расстояний в (4) | каждая пара один раз, деление на n(n − 1)/2 | каждая пара один раз, деление на n² − n: среднее расстояние вдвое меньше |
| ModifiedSpectrumFFTAlgo | 1 − отношение > acc | отношение < acc (без «1 −»). Порог acc = 0.79 из ВКР в Python означает отношение < 0.79, в C — отношение < 0.21 |
| frequency | число измерений между проверками | число проверок до max_iter |
| Длина окна | ratio · cur_iter на окно | суммарная доля всех окон / число окон (при параметрах ВКР — те же 0.2 на окно) |
| Начало окна | rand() % (cur_iter − длина): последнее положение не выбирается | randint(0, cur_iter − длина) включительно |

## Известные ограничения

- Если скалярная величина во всех окнах равна нулю (например, дисперсия
  постоянной серии), отношение min/max равно 0/0, критерий не выполняется
  никогда.
- При window_amount < 2 в критерии (4) нет пар окон: деление на ноль.
- Окна выбираются через `rand()` без явного `srand`, последовательность
  одинакова от запуска к запуску.

Проверка исправлений: `deviation_counter` и `fft_power_spectrum_counter` на
окне {10, 12, 11, 15, 9, 13, 10, 14} совпадают с `numpy.var` (3.9375) и
`numpy.abs(numpy.fft.rfft)` (94, 1.082, 4.472, 2.613, 14).
