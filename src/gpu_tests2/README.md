# gpu_tests2 — модуль измерения задержек между GPU на C

Переписанный на C модуль `src/gpu_tests` (C++). Ключи командной строки, формат вывода (`.txt`, `raw/*.raw`,
`*.sprobe`, `*.scpu`), режимы и методика (`--order random`, `--prespin-sec`, `--probe`) — те же.
Скрипты обработки gpu_tests (`analysis/`) читают его результаты без изменений.

## Чем отличается от gpu_tests

1. **Язык — C (gnu11)**, как остальной clustbench (`src/network_test`). Вместо `std::string`,
   `std::vector`, классов буферов — массивы, `snprintf`, явное освобождение памяти.
2. **Среда host задаётся настройками UCX, а не кодом программы.**
   - gpu_tests: программа сама копирует сообщение целиком GPU → RAM (`cudaMemcpy`), передаёт буфер в RAM
     через MPI и копирует RAM → GPU; внутри узла — через общий буфер в RAM без MPI.
   - gpu_tests2: буферы в памяти GPU, как в custom, отдаются MPI. UCX запрещены прямые пути:
     ```
     UCX_TLS=cuda_copy,<ib>,cma,sm,self   # без cuda_ipc
     UCX_IB_GPU_DIRECT_RDMA=n              # без GPUDirect RDMA
     UCX_RNDV_FRAG_MEM_TYPE(S)=host        # промежуточные буферы передачи частями — в RAM
     UCX_NET_DEVICES=<ближайший к GPU IB>  # как в custom
     ```
     UCX сам копирует через RAM (`cuda_copy`), большие сообщения — частями, совмещая копирование с передачей
     (pipeline). Поэтому **host gpu_tests2 и host gpu_tests — разные среды**: на больших сообщениях первая,
     скорее всего, быстрее. Сравнивать данные host между модулями нельзя; в шапке результатов строки
     `Implementation: C (gpu_tests2)` и `Host staging: ucx`.
   - Имя переменной для типа памяти промежуточных буферов в разных версиях UCX разное (с 1.18 по умолчанию
     они в VRAM). `build/build.sh` берёт его из `ucx_info -c` той сборки UCX, с которой собирается
     программа, и печатает; если не нашёл — предупреждение при сборке и в шапке результатов.
3. **Нужна CUDA-aware MPI.** Прежний запасной путь «MPI без CUDA → копировать через RAM» убран: буферы всегда
   в памяти GPU, без поддержки CUDA программа завершается с ошибкой.
4. **`--sys-via-host` остался копированием силами программы** (общий буфер узла в RAM): он касается только
   пар GPU разных процессоров, а переменные UCX действуют на весь процесс сразу.
5. **Одновременные режимы** проще: копирования через RAM в коде больше нет ни в одной среде.
6. **Случайный порядок** пар и раундов — свой генератор (splitmix64 + Фишер — Йейтс) вместо `std::mt19937`:
   с тем же `--seed` порядок другой, чем в gpu_tests, статистически равноценный. Порядок строк в тесте L3
   (`--probe`) тоже другой — абсолютные значения теста сравнивать между модулями осторожно.

Что не изменилось и почему результаты custom и default должны совпасть с gpu_tests: между отметками
`MPI_Wtime()` стоят те же вызовы — синхронизация пары, `MPI_Send`/`MPI_Recv` (или `Isend`/`Irecv` + `Wait`)
и `cudaDeviceSynchronize` у получателя. Синхронизация устройства теперь стоит и в host (буфер в VRAM:
`cuda_copy` UCX может завершить MPI раньше копии).

## Сборка и запуск

Open MPI и UCX — общие с gpu_tests (`../gpu_tests/build/build_ucx.sh`, `build_openmpi.sh`), версии и
раздел — `../gpu_tests/config.sh` (подключается из `config.sh`).

```
bash build/build.sh                    # программа gpu2-ucx-<версия> здесь (через srun на узле с GPU)
bash submit.sh task.sbatch host_proto  # таблицы протоколов UCX в host и custom (см. experiments/host_proto.conf)
bash submit.sh task.sbatch main        # основной эксперимент; main.conf копируется из gpu_tests
```

Скрипт задания общий — `../gpu_tests/task.sbatch`: он берёт `config.sh`, `experiments/`, программу и пишет
`results/` в каталоге отправки, то есть здесь. Описание эксперимента, которого нет в `experiments/`,
`submit.sh` копирует из `../gpu_tests/experiments` при первом запуске.

## Проверка перехода на C

1. `host_proto` — убедиться, что в host нет `cuda_ipc` и прямой регистрации VRAM на адаптере.
2. `main` двумя–четырьмя независимыми заданиями на g5500-4/5:
   `bash experiments/submit_series.sh main 4` (копия скрипта gpu_tests, ставит задания программы gpu2).
   Эталон — hyp_12025, hyp_12027, hyp_12030, hyp_12266 (C++, те же узлы, тот же main.conf). custom: медианы
   пар по методике должны попасть в разброс между заданиями C++ (±5%). host: ожидается расхождение —
   это другая среда (копирование силами UCX частями против копирования силами программы целиком).

Проверено без кластера (MinGW gcc с заглушками MPI и CUDA): компиляция с `-Wall -Wextra -Wpedantic`,
формат строк `pair`, `verify`, `.raw`, `.sprobe`, медиана и дисперсия, метки рангов, разбор `--gpus`,
перестановка пар. На кластере программа ещё не собиралась.
